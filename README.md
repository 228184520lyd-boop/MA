# Mirror Abyss / 镜渊

Mirror Abyss 是面向 SillyTavern 的长期剧情记忆管理扩展。它以 **SillyTavern World Info / 世界书作为唯一长期事实源**，负责把聊天中已经发生的变化整理进世界书，并在长期游玩中逐层总结、合并与提炼。

当前版本：**4.0.134**  
最低 SillyTavern：**1.18.0**

## 运行原理

```text
AI 回复完成
→ 可选：终稿处理
→ 提取本轮已经发生的重要变化
→ 新的「场景」条目出现时，关闭上一 SceneGroup
→ 小总结：根据已结束场景材料进行总结、合并与提炼
→ 达到累计阈值时执行大总结
→ 写入本轮提取，登记新场景与回执
→ SillyTavern 原生 World Info 负责后续召回
```

插件不维护第二套剧情数据库，也不自行判断剧情事实。语义理解、提取、总结和提炼交给模型；插件只负责 UID、格式、任务生命周期、世界书读写与 UI。

## 使用要求

- 使用能够稳定遵守镜渊输出格式的模型与连接。
- 世界书是唯一事实源；不建议让多个自动记忆扩展同时修改同一本世界书。
- `场景` 是自动小总结的生命周期锚点：首次进入或真正切换场景时，提取结果需要产生正常的 `[场景][名称][关键词][栏目][事实]` 条目；同一连续场景应保持稳定名称。
- 模型连接、上下文长度与网关稳定性会直接影响提取、总结和整本整理。
- 大规模整本整理会按 SillyTavern token 计数自动分批；单条异常巨大的世界书条目仍可能需要先人工整理。

## 主要功能

- **提取**：记录本轮已经发生的重要变化。
- **小总结**：根据一个已结束场景的材料进行总结、合并与提炼。
- **大总结**：根据多个已完成场景的材料进行更高层级的总结、合并与提炼。
- **终稿处理**：使用玩家填写的唯一要求，对当前 AI 正文执行一次最终处理。
- **历史恢复**：Edit / Swipe / Delete 后，按当前 SillyTavern `world_info_depth` 有限重建受影响范围。
- **整理整本世界书**：逐条整理现有世界书；先生成内存预览，玩家确认后才写入。

## 最短使用方式

1. 在 SillyTavern 中安装扩展并打开一个聊天。
2. 选择当前连接或 Connection Manager Profile，并执行一次 API 测试。
3. 开启需要的自动提取、小总结、大总结与终稿处理。
4. 正常游玩。镜渊写入世界书，SillyTavern 原生 World Info 负责召回。

## 提取后隐藏与近期原文

- 提取成功、世界书写入及回执登记完成后，隐藏窗口外已处理的消息。成功返回无新增事实也会登记来源；失败不推进隐藏。
- “保留最近消息数”默认 10，最少 1；每条用户或 AI 消息计 1 条，系统及其他来源隐藏的消息不占配额。近期原文用于衔接语气、动作和对话，10 不是模型通用最优值。
- 旧存档不补跑历史、不把旧 sources 整批升级为新隐藏资格；原有小总结覆盖继续兼容。新版提取只登记本轮来源。
- 提取后隐藏与原有小总结后隐藏分别开关；大总结不新增隐藏动作。关闭提取隐藏会释放仅由该功能覆盖的消息，小总结覆盖仍有效。
- 点击“保存保留数量”立即调整当前聊天；调大可恢复近期原文。
- “恢复楼层并关闭自动隐藏”恢复当前聊天中镜渊拥有的隐藏消息，并关闭两个自动隐藏开关。设置是插件全局设置，其他聊天以后也不再自动登记新隐藏；按钮不撤销世界书，不重新提取，不恢复玩家或其他插件的隐藏。
- 撤销和回滚继续使用原有回执及场景快照；提取可处理镜渊隐藏的目标消息；终稿处理的最近对话可读取镜渊隐藏的原文。小总结仍读取世界书。
- 隐藏不删除原文；世界书激活仍由 ST 原生规则决定。

## 楼层设置入口

打开镜渊面板 → **维护** → 页面底部 **聊天楼层**。可切换“提取后隐藏旧楼层”及“小总结后隐藏楼层”，保存保留消息数，或恢复楼层。面板顶部显示 4.0.134。

源码包与部署包均包含 `.gitignore`。上传 GitHub 时请完整解压后使用 Git 提交，确保包含该文件；不要只选择文件管理器中默认可见的文件。`index.js` 保持跟踪，以供 ST 直接安装。

## 安装与更新文件

4.0.134 的运行文件为同一目录下的 `manifest.json`、`index.js`、`style.css`。`index.js` 已包含完整插件，不再导入 `dist/app.js`；源码模块仍保存在 `src/`。

- 更新文件后重新载入酒馆页面，面板顶部应显示 4.0.134。若没有，请核对“管理扩展”里当前启用的镜渊版本、分支与安装位置。
- `.gitignore` 需作为文件一并提交；手机文件选择器可能不显示它，可在 GitHub 仓库创建同名文件并填入源码包中的内容。

## 发布包装

部署 ZIP 只包含根目录文件，没有外层目录。源码 ZIP 保留 src/、scripts/、tests/、docs/ 的开发分层。使用平铺包覆盖实际启用的插件目录，关闭解压器“新建同名文件夹”选项。

## 请求失败时的显示

运行页依次显示终稿、提取、总结、写入。当前步骤未结束时，不沿用上一次任务的完成结果；总结失败会保留失败阶段并显示宿主提供的底层原因。其他未能确认的阶段不会标成已完成。

若提示仍只有“Response not OK”，说明宿主没有在该错误对象中提供更详细原因，需要查看对应请求或服务端错误；插件不会猜测状态码、偷偷换连接或把失败当成功。

## 4.0.134 脚本更新

manifest 的 js 入口为 `index.js?v=4.0.134`，磁盘文件仍是根目录 `index.js`。SillyTavern 按这个带版本的URL加载同一文件，避免升级后继续使用旧版本同名脚本的缓存。构建会检查URL版本与manifest一致。

更新到这次版本后，重新载入页面；面板标题应为4.0.134。本次保留132的真实错误原因展示，未更改模型参数、总结提示词或写入顺序。它不代表小总结的底层请求故障已经修复。
